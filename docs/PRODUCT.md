# SCIP 供应链智能平台 · 产品说明

> **文档版本**：2026-07-21  
> **产品形态**：可演示的端到端产品原型（Mock 数据 + 完整交互闭环）  
> **技术栈**：React · TypeScript · Vite · Tailwind CSS · Zustand · Recharts · Leaflet  

本文档用于产品介绍、Case Study 与演示脚本。**请明确：当前为验证方案的演示系统，尚未对接生产 ERP/WMS/TMS。**

**作者：** 何欣桐（He Xintong）

---

## 1. 一句话定位

**SCIP（Supply Chain Intelligence Platform）** 是面向化工供应链场景的智能控制塔：把采购、库存、仓储、物流、交付与风险放在同一套「看得见、管得了、能闭环」的操作系统里；并通过 **SCIP Marketplace** 将履约能力开放给下游客户，形成「客户下单 → SCIP 履约 → 客户收货」的商业延伸。

---

## 2. 为什么要做这个平台？

### 2.1 业务背景

化工供应链链路长、SKU 多、异常代价高（延误、缺货、危化合规）。传统做法往往是：

- ERP / WMS / TMS / 邮件微信多系统并行；
- 异常靠人催、对表、开会；
- 总监、采购、物流、客服看到同一张「大表」，噪音大、权限不清；
- 下游客户询价下单靠线下，订单状态不透明。

SCIP 的目标不是再造一套 ERP，而是补齐 **决策与协同层**：

| 层级 | 典型系统 | SCIP 的位置 |
|------|----------|----------------|
| 交易记录 | ERP / 订单系统 | 不替代，未来对接 |
| 库存执行 | WMS | 不替代，展示水位与补货入口 |
| 运输执行 | TMS | 不替代，展示在途与异常 |
| **异常 · 协同 · 决策** | 报表 / Excel | **SCIP 控制塔 + 闭环 + 助手** |
| **客户自助采购** | 邮件 / 线下 | **Marketplace 门户** |

### 2.2 产品目标（本期已验证）

1. **一张控制塔**：健康度、时效、成本、供需、质量与 Top 异常可下钻。  
2. **角色权限**：四类角色看到不同模块与数据范围。  
3. **补货闭环**：从库存红灯 → 发起 → 状态机跟踪 → 入库。  
4. **客户门户**：选品、询价、转单、物流地图、与内部交付台账双向同步。  
5. **智能助手 Scippy**：日常问答 + SOP 推送，浮窗与对话台同一会话。

## 3. 服务谁？原来有什么问题？解决了谁的问题？

### 3.1 用户画像

#### A. SCIP 内部用户

| 角色 | 典型诉求 | 平台对应能力 |
|------|----------|--------------|
| 控制塔总监 | 端到端健康度、异常优先级 | 控制塔看板、全域控制塔、用户管理 |
| 采购经理 | 订单生命周期、供应商协同、补货 | 采购订单、供应商协同、寻源、补货闭环 |
| 物流 / 仓储主管 | 库存灯色、在途异常、入库 | 库存、仓储、物流、关务、闭环 |
| 客服专员 | 交付状态、投诉闭环 | 客户交付、物流只读、工作台 |

#### B. Marketplace 外部用户

- 下游制造企业、贸易商的采购 / 供应链人员  
- 诉求：自助选品、询价、下单、追踪物流，减少反复问询

### 3.2 原有痛点 → 平台解法

| 原有问题 | 影响对象 | SCIP 解法 |
|----------|----------|------------|
| 信息孤岛，开会靠对表 | 总监 / 全员 | 控制塔 KPI + 图表 + TopExceptions |
| 缺货发现晚，补货跨系统 | 采购 / 仓储 | 库存灯色 + 一键补货闭环 + 流程跟踪 |
| 在途异常靠电话催 | 物流 / 客服 | 在途监控 + Marketplace 物流地图 |
| 全员看全表，权限噪音大 | 各角色 | RBAC：导航与操作按角色过滤 |
| 客户问「货到哪了」 | 客服 / 销售 | Marketplace 订单与追踪；内部交付台可见门户单号 |
| 找数、问 SOP 成本高 | 一线运营 | Scippy 助手（规则意图 + 话术 + 主动 SOP） |

### 3.3 「解决了谁的问题」一句话

- **主用户**：内部运营角色（总监 / 采购 / 物流 / 客服）——提升异常可见性与闭环效率。  
- **扩展用户**：下游采购客户——自助采购与履约可视。  
- **平台方**：把履约能力产品化，探索 Marketplace 增量收入。

## 5. 核心能力说明

### 5.1 供应链控制塔

- 全局筛选、自动刷新（演示 30s）  
- KPI 卡片可下钻抽屉  
- 健康趋势 / 雷达、交期、成本、供需、质量  
- Sankey / Gauge / Gantt / Funnel 等补充视图  
- TopExceptions 异常清单  

**设计意图**：让总监先看「哪里不健康」，再下钻，而不是淹没在明细表。

### 5.2 角色与权限（RBAC）

- 四角色模板权限见 `src/config/roles.ts`  
- 路由 `PermissionGate`：无权限进 403  
- 侧栏按 `canView` 过滤；**顶栏提示当前角色隐藏了多少模块**（避免误以为「功能丢了」）  
- 登录弹窗可选演示账号；退出自动弹出登录框  

**演示账号推荐**：张伟 `EMP-001`（控制塔总监）— 可见全部模块含用户管理。

### 5.3 补货闭环

- 库存页发起 → `useFlowStore` + 状态机 `orderMachine`  
- 流程跟踪页可视化状态  
- 仓储到货 / 入库确认可推进  

**设计意图**：把「发现 → 决策 → 执行 → 回写」做成可演示的状态机，而不是静态页面。

### 5.4 Scippy 助手

- 浮窗快捷对话 + `/ai` 全屏对话台，**同一 Zustand 会话**  
- 意图匹配 + 业务 / 日常话术；主动 SOP 推送  
- 表情仅开心 / 紧急，符合品牌人设  

**取舍**：本期用规则引擎保证可控可演示；下一阶段可接 LLM + Tool Calling。

### 5.5 SCIP Marketplace

- 橙白友好风格，与内部蓝白差异化  
- 产品 / 库存来自 SCIP 物料 Mock（销售价 = 成本价加成）  
- 询价 → 报价（种子单可转单）→ 订单 → Leaflet 追踪  
- **看市场**：行业头条 / 热门品类 / 展会  

### 5.6 双向订单同步（本期强化）

| 方向 | 行为 |
|------|------|
| Marketplace → SCIP | 转单 / 种子订单写入 `useChannelSyncStore` |
| SCIP 可见 | 「客户交付」页顶部 **Marketplace 渠道订单** 表（SCIP 单号 ↔ 门户单号互链） |
| Marketplace → SCIP | 客户确认收货，回写渠道订单状态为已完成 |

相关代码：

- `src/services/channelSync.ts` — 映射与单号规则  
- `src/store/useChannelSyncStore.ts` — 共享状态  
- `src/pages/Delivery.tsx` — 内部可见看板

## 6. 数据说明（常见问题）

### 6.1 数据是否真实？

- **行业问题真实**：化工库存周转、OTIF、在途异常、合规是常见议题。  
- **本系统数据为结构化 Mock**：物料、库存灯色、采购单、交付单、物流轨迹、资讯等，用于验证交互与角色模型。  
- **尚未对接**真实 ERP / WMS / TMS / 主数据。

### 6.2 若落地，优先对接什么？

1. 物料主数据 + 库存可用量（只读）  
2. 采购订单 / 客户订单状态事件  
3. 运单轨迹与异常事件  
4. 组织与账号（替换本地演示登录）

## 7. 「有没有人用过」与迭代反馈

本期以**产品演示与评审反馈**驱动迭代（非生产埋点）。代表性改动：

| 反馈 | 改动 |
|------|------|
| Scippy 与 AI 助手重复 | 合并为同一会话，双入口 |
| 助手表情不宜消极 | 仅开心 / 紧急 |
| 工作台太薄 | 待办、闭环看板、角色专属看板 |
| 头像与登录体验差 | 浅色全名头像；登录弹窗；退出可再登 |
| 切角色后「模块消失」 | 顶栏权限提示 + 补齐部分角色可见模块 |
| 需要客户侧故事 | Marketplace 门户 + 看市场 + 渠道订单同步 |
| Banner 体验 | 亮色插画、自动轮播、左右翻页 |

## 8. 关键取舍

| 决策 | 选择 | 放弃 / 延后 | 理由 |
|------|------|-------------|------|
| 数据 | Mock + 状态机 | 先接真实 API | 先验证闭环与角色，避免卡在集成 |
| AI | 规则意图引擎 | 大模型 API | 可控、可演示、无密钥依赖 |
| 工程 | 单仓双门户 | 两个独立仓库 | 共享库存与渠道订单，演示「数据同源」 |
| 权限 | RBAC 过滤导航 | 全员全菜单 | 贴近真实组织；用提示解释「菜单变少」 |
| Scippy | 一脑双入口 | 删浮窗或删全屏 | 伴随场景 vs 深度对话 |
| Marketplace 视觉 | 橙白卡片 | 复用内部蓝白表格 | 内外用户心智不同 |
| 测试 | 核心纯函数 Node 单测 | 全量 E2E | 先锁住同步与权限关键逻辑 |

## 10. 三分钟演示脚本（建议背熟）

**准备**：登录 **张伟 EMP-001（控制塔总监）**。

| 时间 | 动作 | 讲述要点 |
|------|------|----------|
| 0:00–0:30 | 控制塔首页 | 「一张图看健康度与 Top 异常，不是再做 ERP」 |
| 0:30–1:00 | 切到物流主管再切回总监 | 「RBAC：菜单按角色变；顶栏提示隐藏模块；总监看全量」 |
| 1:00–1:40 | 库存 → 补货闭环 → 流程跟踪 | 「红灯 → 发起 → 状态机跟踪，闭环可演示」 |
| 1:40–2:20 | 侧栏进 Marketplace | 「橙白门户；选品询价；已报价单可转订单」 |
| 2:20–2:50 | 门户订单详情 → 客户交付 | 「MO 与 CO 单号互链；确认收货回写 SCIP」 |
| 2:50–3:00 | Scippy 问「今天有什么异常」 | 「一脑双入口；规则引擎可控，下一步可接 LLM」 |

**备用账号**：采购李娜 EMP-002、物流王强 EMP-003、客服陈静 EMP-004。

## 13. 电梯稿（30 秒）

> SCIP 解决化工供应链「看不见、难协同、闭环断」的问题。服务内部总监/采购/物流/客服，并把履约能力延伸到下游 Marketplace。我们用可运行原型把控制塔、RBAC、补货状态机和客户门户串起来；数据目前是 Mock，但渠道订单已双向同步可点。取舍上优先把闭环和角色体验做透，真实系统对接放在验证通过之后。
